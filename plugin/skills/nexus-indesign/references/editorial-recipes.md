# Recettes éditoriales

Utiliser ces recettes comme systèmes de décision, jamais comme styles prêts à copier. Partir du contenu, de la marque, du format et des assets réels. Conserver une exception lorsqu'elle sert clairement l'intention ; éviter la variété décorative sans fonction.

## Formaliser la direction visuelle

Écrire cette fiche avant toute création ou refonte importante :

| Décision | Contenu attendu | Preuve dans InDesign |
|---|---|---|
| Intention | Trois adjectifs compatibles avec le public et le message | Hiérarchie et traitement visuel reconnaissables sur les pages témoins |
| Priorité de lecture | Élément d'entrée, second niveau, lecture approfondie | Ordre perceptible à petite échelle puis confirmé à taille de lecture |
| Grille | Marges, colonnes, gouttières, modules et ligne de base | Guides, gabarits et alignements communs |
| Typographie | Rôles titre, chapô, texte, légende, donnée et navigation | Styles nommés ; aucune fonte inventée ou substituée sans accord |
| Couleur | Rôles fond, texte, accent, information et alerte | Nuances nommées ; contraste et espace colorimétrique vérifiés |
| Espacement | Petite unité et séquence d'intervalles cohérente | Valeurs répétées dans les styles et gabarits |
| Images | Ratio, cadrage, point focal, fond, bord et légende | Styles d'objet, résolution effective et liens sains |
| Motif | Un signe récurrent utile : filet, cartouche, folio ou repère | Répétition maîtrisée, jamais ajoutée pour remplir le vide |

Tester la proportion dorée pour une relation principale/secondaire, une échelle ou un espacement seulement si elle améliore réellement le rendu. Comparer avec une proportion simple avant de retenir la meilleure.

Si une référence visuelle est fournie, relever séparément sa grille, sa densité, ses rôles typographiques, son contraste, son rythme, son traitement d'image et ses motifs. Réutiliser les principes compatibles avec le brief sans reproduire une composition distinctive.

## Choisir les pages témoins

Sélectionner trois à cinq témoins avant de déployer le système :

| Témoin | Ce qu'il éprouve |
|---|---|
| Couverture ou ouverture | Impact, promesse, marque et hiérarchie maximale |
| Page dense | Texte long, notes, tableaux, produits ou données |
| Page légère | Blancs, rythme, transitions et respiration |
| Page image | Cadrage, légendes, crédits et relation texte-image |
| Double page | Pli, équilibre, continuité et concurrence entre pages |
| Navigation | Sommaire, folios, onglets, index ou repères de chapitre |

Rendre et accepter les témoins avant de créer les variantes. Pour un document court, combiner plusieurs fonctions dans un même témoin sans omettre la page la plus dense.

## Magazine

### Construire

- Définir couverture, sommaire, ouverture de rubrique, article long, brève, page image et colophon selon le contenu réel.
- Utiliser une grille modulaire assez souple pour produire une cadence sans perdre les axes communs.
- Distinguer clairement voix éditoriale, titre, chapô, texte, citation, légende, crédit et folio par des styles.
- Alterner densité et respiration à l'échelle des doubles pages ; réserver les ruptures fortes aux ouvertures et sujets majeurs.
- Protéger le texte et les visages du pli ; contrôler la continuité d'une image traversante sur la planche.

### Témoins obligatoires

Rendre la couverture, une ouverture en double page, un article dense et une page image. Vérifier l'ordre de lecture, la longueur des lignes, les légendes, les crédits, les folios et la cohérence entre rubriques.

## Brochure premium

### Construire

- Organiser une séquence courte : promesse, contexte, preuve, offre, bénéfice, appel à l'action et contact selon les contenus fournis.
- Donner une fonction principale à chaque double page et limiter les signaux concurrents.
- Utiliser les blancs, les détails d'image et les changements d'échelle comme rythme, pas comme remplissage.
- Vérifier pagination, plis, reliure, fond perdu et finitions à partir des spécifications réelles de production.
- Rendre l'appel à l'action lisible et cohérent avec la marque sans transformer toutes les pages en publicité.

### Témoins obligatoires

Rendre la couverture, la double page de promesse, la page la plus informative et la dernière page. Pour une brochure pliée, contrôler aussi chaque panneau dans son ordre physique réel.

## Rapport

### Construire

- Définir couverture, synthèse, sommaire, ouverture de chapitre, page narrative, page de données, tableau, méthodologie et annexes nécessaires.
- Donner une navigation stable par gabarits, folios, titres courants et repères de section.
- Hiérarchiser tableaux et graphiques par message, source, unité, légende et annotation ; ne pas décorer au détriment des données.
- Préserver la comparabilité des valeurs, l'alignement des nombres et la lisibilité des notes.
- Prévoir les cas longs : titres sur deux lignes, tableaux multipages, notes, légendes et références croisées.

### Témoins obligatoires

Rendre la synthèse, une ouverture, la page de texte la plus dense, un tableau ou graphique représentatif et une annexe. Contrôler navigation, cohérence des données, veuves, orphelines et fractionnement des tableaux.

## Couverture complète

### Construire

- Traiter quatrième, dos, tranche et première comme une seule surface lorsque le façonnage le demande.
- Exiger le format fini, le fond perdu, les zones de sécurité, le sens de lecture, le type de reliure et l'épaisseur de tranche fournie par l'imprimeur.
- Réserver les zones réelles pour logo, résumé, prix, ISBN ou code-barres sans inventer ces contenus.
- Vérifier le titre en vignette, à distance de lecture et à taille réelle.
- Contrôler le passage des fonds et images sur les plis, mors, tranche et chants.

### Limite obligatoire

Ne jamais calculer ni finaliser une tranche sans spécification d'imprimeur fondée sur papier, pagination et reliure. En son absence, produire seulement une piste de première de couverture clairement marquée non prête pour production.

### Témoins obligatoires

Rendre la surface complète avec repères de zones, puis la première seule en vignette et à taille de lecture. Vérifier continuité, contraste, sécurité et absence de contenu critique dans les zones techniques.

## Catalogue

### Construire

- Valider champs, unités, variantes, prix, identifiants, images et règles de tri avant toute fusion de données.
- Définir ouverture de catégorie, produit vedette, grille standard, variante dense, comparaison, index et mentions selon le corpus réel.
- Stabiliser le ratio des images, la position des titres, les attributs, les prix, les références et les appels à l'action par styles et gabarits.
- Prévoir les données manquantes, les libellés longs, les variantes nombreuses et les produits sans image sans inventer de contenu de remplacement.
- Demander l'accord explicite avant la fusion, puis contrôler un échantillon aux extrêmes avant de générer tout le catalogue.

### Témoins obligatoires

Rendre une ouverture de catégorie, une fiche standard, la fiche la plus dense, une page comparative et l'index. Vérifier au moins un libellé long, une donnée absente autorisée, une image atypique et une rupture de catégorie.

## Accepter ou corriger

Pour chaque témoin, classer les observations sans score moyen :

- **Bloquant :** ordre de lecture ambigu, texte illisible ou débordant, contenu critique dans une zone technique, donnée trompeuse, image déformée ou insuffisante, contraste non acceptable, lien ou fonte manquante.
- **À corriger :** alignement isolé, espacement incohérent, rythme monotone, hiérarchie trop faible, légende mal rattachée, variation locale non justifiée ou rupture involontaire entre pages.
- **Intention assumée :** exception visible, cohérente avec le brief, reproduite seulement là où elle sert le message et confirmée par le rendu.

Corriger d'abord tous les défauts bloquants, puis les incohérences systémiques. Effectuer au plus trois cycles avec une hypothèse différente par cycle. Après acceptation des témoins, déployer les styles et gabarits, rendre un échantillon final réparti dans le document, lancer le préflight et comparer l'empreinte de mise en page.

## Recettes de script

Trois scripts éprouvés dans InDesign 2026, à passer tels quels dans `code` de `run_layout_script` avec leur `input`. Aucun n'utilise `await` avant ses modifications : chacun forme une seule étape d'annulation nommée « Nexus : <reason> ». Chacun renvoie de quoi vérifier sans relire tout le document ; regarder ensuite la vignette jointe.

### Remplir des champs `{{nom}}`

`input` : `{ "values": { "titre": "…", "date": "…" } }`. Renvoie le nombre de remplacements par champ et la liste des champs restants (`remaining`) : ne jamais inventer une valeur manquante, la demander.

```js
// input: { values: { "titre": "…", "date": "…" } } ; chaque {{nom}} connu prend sa valeur, le reste est listé.
const values = input.values || {};
const grep = (pattern) => {
  app.findGrepPreferences = indesign.NothingEnum.NOTHING;
  app.findGrepPreferences.findWhat = pattern;
  try { return doc.findGrep(); } finally { app.findGrepPreferences = indesign.NothingEnum.NOTHING; }
};
const escape = (text) => text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
const replaced = {};
for (const [name, value] of Object.entries(values)) {
  const found = grep("\\{\\{\\s*" + escape(name) + "\\s*\\}\\}");
  for (let index = found.length - 1; index >= 0; index -= 1) found[index].contents = String(value);
  replaced[name] = found.length;
}
const remaining = [...new Set(grep("\\{\\{[^{}]+\\}\\}").map((text) => String(text.contents).slice(2, -2).trim()))];
return { replaced, remaining };
```

### Chaîner des pages jusqu'à zéro texte en excès

`input` : `{ "frameId": <id d'un bloc du récit>, "maxPages": 50 }`. Ajoute en fin de document une page et un bloc chaîné aux marges (mêmes colonnes) tant que le récit déborde. `stillOverset: true` au plafond : revoir le corps, la grille ou le contenu plutôt qu'augmenter `maxPages`. Rendre ensuite les pages ajoutées (`previewPages`).

```js
// input: { frameId: <un bloc du récit>, maxPages: 50 } ; ajoute pages et blocs chaînés tant que le récit déborde.
const story = doc.pageItems.itemByID(input.frameId).getElements()[0].parentStory;
const containers = story.textContainers;
let last = containers[containers.length - 1];
const leftHand = indesign.PageSideOptions.LEFT_HAND;
let added = 0;
story.recompose();
while (last.overflows && added < (input.maxPages || 50)) {
  const page = doc.pages.add(indesign.LocationOptions.AT_END);
  const [top, left, bottom, right] = page.bounds;
  const margins = page.marginPreferences;
  let inside = margins.left, outside = margins.right;
  if (doc.documentPreferences.facingPages && page.side === leftHand) [inside, outside] = [outside, inside];
  const next = page.textFrames.add({ geometricBounds: [top + margins.top, left + inside, bottom - margins.bottom, right - outside] });
  next.textFramePreferences.textColumnCount = last.textFramePreferences.textColumnCount;
  next.textFramePreferences.textColumnGutter = last.textFramePreferences.textColumnGutter;
  last.nextTextFrame = next;
  last = next;
  added += 1;
  story.recompose();
}
return { pagesAdded: added, stillOverset: last.overflows, pages: doc.pages.length };
```

### Réparer des liens par nom de fichier

`input` : `{ "folder": "C:/Projet/Images" }`. Relie chaque lien manquant au fichier de même nom (casse ignorée) du dossier ; `notFound` liste ceux sans correspondance, `stillMissing` ce qui reste à traiter. Un fichier déplacé hors d'InDesign change l'empreinte du document : relire `silent_inspect_document` avant le script.

```js
// input: { folder: "C:/Projet/Images" } ; chaque lien manquant est relié au fichier de même nom dans ce dossier.
const fs = require("fs");
const folder = String(input.folder).replace(/\\/g, "/").replace(/\/+$/, "");
const files = new Map(fs.readdirSync(folder).map((name) => [name.toLowerCase(), name]));
const missing = String(indesign.LinkStatus.LINK_MISSING); // les énumérations UXP sont des objets : comparer leur texte
const relinked = [];
const notFound = [];
for (const link of doc.links.everyItem().getElements()) {
  if (String(link.status) !== missing) continue;
  const match = files.get(String(link.name).toLowerCase());
  if (!match) { notFound.push(link.name); continue; }
  link.relink("file:" + folder + "/" + match); // relink attend une URI file:, pas un chemin nu
  relinked.push(link.name);
}
const stillMissing = doc.links.everyItem().getElements().filter((link) => String(link.status) === missing).map((link) => link.name);
return { relinked, notFound, stillMissing };
```
